## Fixed — please re-test

- [x] **Selecting the "Bold" (נועז) theme in the dashboard loaded the Classic renderer instead of Dark.** Real root cause: the dashboard's theme picker (`components/dashboard/BrandingEditForm.tsx`) writes `selected_theme = 'bold'` to the DB when a studio picks that theme — not `'dark'`. The old iframe system already accounts for this (`PhotographerHomepage.tsx`'s `themeMap` maps both `'bold'` and `'dark'` to its dark renderer), but all 6 of my new dispatch branches only checked `selected_theme === 'dark'`, so a real studio on the Bold theme silently fell through to the Classic default. Fixed all 6 `page.tsx` files to check `selected_theme === 'dark' || selected_theme === 'bold'`, matching the old system's mapping exactly.

- [x] **Same-page anchor links (nav → section) didn't scroll; cross-page "Contact" link from the blog page didn't reach the homepage's contact section.** Real root cause: nav links use a `?section=xxx` query param (`homepageSectionHref`), not a `#hash` — that's the *old* system's own mechanism too (a `<script>` reading `window.location.search` and scrolling), but nothing in the new React homepage ever read that query param. Added `components/photographer/themes/shared/ScrollToInitialSection.tsx` (ports the old script's exact behavior — reads `?section=`/`#hash`, retries up to 30× at 100ms since content may not be in the DOM yet, `scrollIntoView({behavior:'smooth'})`, then cleans the URL) and wired it into both `ClassicHomePage.tsx` and `DarkHomePage.tsx`. This fixes both reported symptoms at once, since both nav-on-homepage and nav-from-another-page point at the exact same mechanism.
- [x] **Blog section title on the homepage was missing its Hebrew text — only showed "Blog" (the English decorative eyebrow, correctly always-English) with an empty title next to it.** Real root cause, and it turned out to be systemic: the old system has 6 separate theme+language-aware "resolve this section's title, falling back to a real default when the studio hasn't set one" helpers (`resolveGalleriesSectionTitle`, `resolveRecentPhotosSectionTitle`, `resolvePostsPageTitle`, `resolvePackagesSectionCopy`, `resolveTestimonialsSectionTitle`, `resolveContactSectionCopy`) — my adapter bypassed every one of them with a bare `|| ''`, so any section whose title field is empty in the DB (the common case) rendered with a blank title instead of the theme's real default. Fixed for **all 6** titles/subtitles across both classic and dark (not just blog) — moved the raw DB value through the theme-agnostic core view model, resolved to its real default inside each theme's own shaper (`toClassicHomePageProps`/`toDarkHomePageProps`), matching the theme name each resolver actually expects.
